02 · 문제02 / 24

직접 호출은 콜그래프에 있고, 간접 호출은 없다

질문 — "RemoteStartTransaction"은 어느 C 함수가 처리하나?

remote_handler(f); // 직접 호출 — 대상 이름이 코드에 있음 → 콜그래프 O Entry e = g_table[ f->action ]; // 테이블에서 함수 포인터를 꺼내 e.fn(f->payload); // 간접 호출 — 대상은 런타임 값 → 콜그래프 ✕
문제우리가 필요한 건 "RemoteStartTransaction" → remote_handler() 라는 간선이다. 단순 대안콜그래프를 따라간다 → 간접 호출 지점엔 대상 간선이 아예 없어 끊긴다. 그래서호출이 아니라 “그 포인터가 어디서 채워졌나”(등록)를 봐야 한다.
F2-A · 핸들러 해석
다음 → 그 “등록”과 “후보”란 정확히 무엇?
발표 노트

직접 호출 = callee 이름이 코드에 박힘(정적 간선 O). 간접 호출 = 저장된 함수 포인터 호출(정적 간선 ✕). 보안 질문은 액션 단위라, 그 액션의 핸들러 함수를 먼저 알아야 오염 분석이 시작된다.

07 · 상관의 건전성07 / 24

왜 이 두 필드를 “하나의 등록”으로 묶어도 되나

질문 — 어떤 상관이 안전하고, 어디서 멈춰야 하나?

안전 — 묶어도 됨
{ .action = ACTION_REMOTE_START, .fn = remote_handler }
· 같은 aggregate 초기화에 속함
· .action·.fn은 서로 다른 의미 필드
· 콜백이 내부 함수 심볼로 해석됨
· 객체 간 교차 짝짓기 없음 · 위치/부모 보존
위험 — 묶으면 안 됨
table[i].action = ACTION_REMOTE_START; table[j].fn = remote_handler; // i == j 를 증명할 수 없음
같은 슬롯임을 정적으로 증명 못 하면 쌍을 만들지 않는다 → 잘못된 짝보다 보류가 옳다.
구조 상관은 “같은 슬롯”이 정적으로 확실할 때만 성립 — 규칙이 어디서 멈추는지가 정확성의 핵심이다.

12 · 독립 근거 결합12 / 24

독립 그룹은 noisy-OR로 — 대안은 왜 나쁜가

질문 — 서로 다른 사이트의 확증은 어떻게 더하나?

결합식문제
MAX과대계산 방지 O · 독립 확증 무시 ✕
SUM확증 보상 O · 1 초과·과속 ✕
AVERAGE유계 O · 유효 약근거가 평균을 낮춤 ✕
NOISY-OR1 미만 유계 · 그룹마다 ↑ · 체감
그룹 A = 0.80,  B = 0.49 1 − (1−0.80)(1−0.49) = 1 − 0.20×0.51 = 0.898
두 약한 독립 근거가 각자보다 커지되, 1엔 못 미친다
정직하게: 그룹을 근사적으로 독립이라 가정한 공학적 결합 모델이다 — 보정된 통계 확률이 아니다.

다음 → 그럼 약한 근거가 쌓이면?
발표 노트

MAX는 확증 무시, SUM은 1 초과, AVERAGE는 약근거가 평균을 깎음. noisy-OR만 유계+확증 반영+체감. 독립 가정은 근사; 순위용 점수이지 확률 아님 — 연구 청중에 중요한 구분.

24 · 알고리즘 재구성24 / 24

전체 알고리즘 — 이제 “왜”까지 재구성할 수 있다

핵심 — 인식과 판정의 분리가 이 설계의 기여다.

# 액션 a ev = dedupe( ⋃ extractor(a) ) # 인식 → 증거(관찰만) for e in ev: e.score = Prior(e.kind) × MatchMult(e.match) # 곱 = 구조 AND 식별자 for cand in group_by_callback(ev): g = { grp: max(score) } # 중복 접기(과대계산 방지) conf = 1 − ∏(1 − g[grp]) # 독립 확증(체감) if no strong match: conf = min(conf, 0.85) # 쌓인 약함 차단 top, second = rank_desc(cands) return UNRESOLVED if top<0.50 # 충분히 강한가 else AMBIGUOUS if top−second<0.15 # 분명히 나은가 else RESOLVED(top) # 아니면 보류 — 오답보다 안전
각 줄의 주석이 “왜”다: 곱=AND 게이트, MAX=과대계산 방지, noisy-OR=독립 확증, cap=거짓 확실 차단, floor·margin=절대·상대, 보류=하류 오염 방지.
