핵심 지점 — 천천히. 단순한 콜그래프 순회는 구조적으로 실패한다. 연결은 초기화 테이블·대입·등록 함수 안에 잠재해 있다. F2-A는 그 잠재 간선을 정적으로 복원한다. “그냥 실행하면?” — 정적·배포 전·전체 펌웨어·하네스 없음.

프로토콜 세계와 코드 세계를 잇는 경첩. 사다리: macro/enum·숫자 ID 일치는 EXACT, 정규화 이름 일치는 NORMALIZED, 부분 문자열은 HEURISTIC_SUBSTRING, ID 없는 이름 유사는 NAME_ONLY. 이후 계산의 “매치 강도”는 전부 여기서 유래. 양방향: KB가 정규 정체성을, 코드가 원시 식별자를 내고 매칭이 대응도를 채점.

07 · 등록 방식07 / 20

핸들러 등록은 형태가 제각각이다

의미는 하나(action ↦ handler), 문법은 여러 가지. 그래서 인식기도 여럿이어야 한다.

집합 초기화 · aggregate
{ ACTION, fn }
지정 초기화 · designated
{ .action = ACTION, .fn = fn }
인덱스 대입 · indexed
handlers[ACTION] = fn
상관 저장 · correlated
t[k].action = ACTION; t[k].fn = fn
등록 함수 · registrar
register(ACTION, fn) → 콜리가 저장
위임 등록 · delegated
register(…) → store_handler(…) → t[.]=fn

발표 노트

의미적 동치 vs 문법적 다양성. 지정 초기화와 집합 초기화는 의미는 같지만 AST에서 구조가 다르다(지정 멤버는 대입으로 감싸짐). 이 다양성 때문에 단일 매처는 취약하다.

09 · 인식 계층09 / 20

후보를 가르는 건 종류가 아니라 매치 강도다

디스패치와 등록의 사전확률은 대등하다 — 어떤 종류도 해석에서 배제되지 않는다.

발표 노트

사전확률은 종류별이며 디스패치는 등록만큼 높다 — 디스패치 매치는 약한 신호가 아니다. 진짜 약한 종류는 이름 전용. weak-only cap은 매치 강도(정확 식별자 없음)에 걸리며 종류가 아니다. 따라서 높은 점수의 후보는 디스패치라도 해석될 수 있다. 구조 종류에만 해석을 예약하는 규칙은 없다. (전체 표는 부록.)

의도적 보류가 가장 흥미로운 지점. 잘못된 해석은 후속 전부를 오염시키므로, 근거가 진짜 갈리면 보류하고 F6/사람에게 넘기는 게 옳다. 모호는 결함이 아니라 기능. 게이트는 임계값+마진뿐 — weak-only cap은 신뢰도를 낮출 뿐 해석을 막지 않으며, 정확 매치의 디스패치는 단독으로도 확정된다.

15 · 사례 분석15 / 20

이 사례에선 디스패치 증거가 이긴다

두 추출기가 발화 — 더 강한 식별자 매치가 확정을 가져간다.

static Reg t[] = { { ACTION_DATA_TRANSFER, foo } }; // 등록 switch (f->action){ case ACTION_DATA_TRANSFER: bar(); } // 디스패치
증거 · EVIDENCE
A · REGISTRATION_INIT → foo  ·  id=ACTION_DATA_TRANSFER (부분 문자열)
B · ENUM_CASE → bar  ·  id=ACTION_DATA_TRANSFER (정규화 일치)
bar · 0.72 vs foo · 0.56 확정 → bar
switch 제거 시 → 증거 A만 → foo 단독 확정 (≈0.56, 임계값 턱걸이)
F2-A · 핸들러 해석 — 기술 설계 리뷰
발표 노트

실제 수치: bar(ENUM_CASE) 사전확률 0.85 × 정규화 매치(×0.85) ≈ 0.72; foo(REGISTRATION_INIT) 0.80 × 부분 문자열(×0.70) ≈ 0.56. 차이 ≈0.16이 모호성 마진을 넘어 디스패치 핸들러 bar로 확정. 해석은 매치 강도 기반이며 종류 무관 — 구조 권한 부여는 없다. 모호를 보이려면 마진 안의 두 후보가 필요.
